# ST Edge AI NPU runtime

The runtime that runs a network on the STM32N6's Neural-ART NPU, ST Edge
AI's, copied verbatim with `npu_cache.c` and `mcu_cache.c`. Nothing here is
edited in this repository.

STMicroelectronics' software, under **SLA0044** (`LICENSE.txt`). It is not
covered by this repository's BSD-3-Clause licence, and may only be used on,
or with, STMicroelectronics devices.

| | |
|---|---|
| `Npu/ll_aton/` | the low-level runtime, `atonn-v1.1.3-275` (`ll_aton_version.h`). A network generated by ST Edge AI refuses to compile against any other version |
| `Npu/Devices/STM32N6XX/` | the NPU's register map, and the CPU and NPU cache maintenance the runtime calls |
| `Inc/` | the network runtime library's headers |
| `Lib/GCC/ARMCortexM55/NetworkRuntime1020_CM55_GCC.a` | the network runtime library, 10.2.0, for the Cortex-M55 with GCC. It carries the software operators a network's hybrid epochs call |

## How it differs from ST Edge AI 4.0's copy

Compared with the runtime ST Edge AI Core 4.0 installs
(`Middlewares/ST/AI`), as the core carries it:

- `ll_aton_runtime.c`: the NPU's error interrupts are acknowledged and
  recorded rather than stopped on, so an application can drop the frame and
  restart the runtime. The records are the `g_aton_err_*` variables.
- `ll_aton_NN_interface.h`: the weights and blob fields of the network
  interface are declared in the order the runtime's initialiser macros fill
  them in. The file carries a note saying why.
- `ll_aton_osal_rtos_template.c` is renamed `ll_aton_osal_rtos_template.h`.
  The FreeRTOS, ThreadX and Zephyr layers include it textually, and the
  rename stops a build that compiles every `.c` file from compiling it on
  its own.
- `ll_aton_stai_internal.{c,h}` and `stai_aton_common.h` are not carried.
- `npu_cache.{c,h}` and `mcu_cache.{c,h}` are an earlier ST version.
  `npu_cache_init()` sets up the runtime's own handle for the NPU cache, and
  an application calls it before using the runtime.
- The network runtime library is 10.2.0, where ST Edge AI 4.0 ships 12.0.1.
  Some headers in `Inc/` differ to match.

## Building with it

The code is built as the core builds it:

- the switches `LL_ATON_PLATFORM=9 LL_ATON_OSAL=5 LL_ATON_SW_FALLBACK=1
  LL_ATON_RT_MODE=2 LL_ATON_DBG_BUFFER_INFO_EXCLUDED=1
  APP_HAS_PARALLEL_NETWORKS=0`, which select the STM32N6 platform, the FreeRTOS
  layer and one network at a time;
- `-O2 -fno-strict-aliasing -std=gnu17`.

The FreeRTOS layer uses static kernel objects, so the kernel needs
`configSUPPORT_STATIC_ALLOCATION`, as `Utilities/freertos/FreeRTOSConfig.h`
sets it.

`neuron6_npu.{h,c}` prepares the NPU before the runtime starts: the bus
rights, the clocks, the RAM banks, the cache and the interrupts.
`Examples/Camera_Nia416Stream_USB_FreeRTOS` puts the whole stack together,
and `harness/examples/addnpu.py` adds it to a CubeIDE project.
